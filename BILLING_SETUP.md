# Striva Премиум — подписка через Google Play Billing

Код готов: плашка «Striva Премиум» на главном, строка статуса в профиле, экран выбора
тарифа (1 / 3 / 12 месяцев) с оплатой через Google Play, проверка покупок на сервере.
Ниже — что сделать руками, по порядку. Шаги 1–3 — до мержа PR, 4–7 — после.

## Как это устроено

- **Оплата** — только через Google Play (политика Play запрещает в приложении из Play любые
  другие способы оплаты цифровых функций; за это в сентябре отклонили версию с Telegram Stars).
- **Приложение** (`frontend/src/lib/billing.ts`, `context/premium.ts`) получает тарифы и цены
  из Google Play (в валюте пользователя), запускает покупку и отправляет `purchaseToken` на
  бэкенд. Цены в коде не хранятся — только в Play Console.
- **Бэкенд** (`backend/billing.py`, `/billing/verify`, `/billing/status`) сам спрашивает у Google
  Play Developer API статус токена, подтверждает покупку (acknowledge — без этого Google вернёт
  деньги через 3 дня) и пишет срок в `profiles.premium_until`. Продление, отмену и возврат
  денег ловит при `/billing/status` (приложение вызывает его при запуске и при возврате в
  приложение). Отдельный Pub/Sub не нужен.
- **Защита**: `premium_until` из приложения не изменить (триггер в `db/phase8_premium.sql`);
  один токен покупки = один аккаунт Striva; при покупке передаётся id пользователя, бэкенд его
  сверяет.

| | Бесплатно | Премиум |
|---|---|---|
| ИИ-чат и совет дня | 30 / день | 200 / день |
| Разбор еды, тренировок, ИИ-планы | по 15 / день | по 100 / день |
| Инструменты тренера (создать клуб, назначить тренировку/питание, запланировать сессию) | — | ✅ |
| Дневник, вес, вода, статистика, роль клиента, просмотр своих клиентов | ✅ | ✅ |

Лимиты меняются в `backend/main.py` (`AI_PREMIUM_*`) и `frontend/src/config/billing.ts`.

## 1) Supabase — выполнить SQL

Supabase → SQL Editor → выполни `db/phase8_premium.sql` (поля `profiles.premium_*`, триггер
защиты, таблица `billing_purchases`). **До** деплоя бэкенда.

## 2) Google Cloud + Play Console — доступ бэкенда к покупкам

Используем тот же сервисный аккаунт, что и для `eas submit`
(`frontend/secrets/play-service-account.json`), Google Play Android Developer API в его
проекте уже включён.

1. Play Console → **Пользователи и разрешения** → сервисный аккаунт (`...@...iam.gserviceaccount.com`)
   → **Разрешения для приложения Striva** → добавь:
   - «Просмотр финансовых данных, заказов и ответов на опросы об отмене подписки»
   - «Управление заказами и подписками»
2. Применение прав в Google иногда занимает до суток. Если бэкенд пишет в логах
   `google 401/403 ... insufficient permissions` — подожди или измени любое описание
   подписки в Play Console и сохрани (это ускоряет применение прав).

## 3) Render — переменная окружения

Render → сервис бэкенда → Environment → добавь:

```
GOOGLE_PLAY_SERVICE_ACCOUNT_JSON = <всё содержимое play-service-account.json целиком>
```

Без неё бэкенд работает как раньше (все бесплатные), а `/billing/verify` честно отвечает
«недоступно».

## 4) Сборка 1.1.0 (нужна новая сборка в Play — OTA не хватит)

В приложение добавлен нативный модуль `expo-iap`, поэтому `runtimeVersion` поднят до `2.1.0`.
Старые сборки (1.0.x) продолжают работать как раньше (бесплатно), но OTA-обновления (`eas update`)
для 2.1.0 до них не доходят — пользователи получат Премиум с обновлением из Play.

```bash
cd frontend
npx expo prebuild --platform android --no-install   # БЕЗ --clean
# android/app/build.gradle: versionCode 4, versionName "1.1.0"
cd android && ./gradlew bundleRelease
```

Залей `app-release.aab` в **Play Console → Тестирование → Внутреннее тестирование** (не сразу в
продакшн: подписку можно создать только после загрузки сборки с биллингом, и её нужно проверить).

## 5) Play Console — создать подписку

1. **Настройки → Профиль платежей**: если ещё не создан — создай (без него раздел подписок
   недоступен; нужен для выплат).
2. **Монетизация → Товары → Подписки → Создать подписку**:
   - ID продукта: `striva_premium` (ровно так — он зашит в приложении и бэкенде)
   - Название: «Striva Премиум»
3. Внутри подписки — **три базовых плана** (ID ровно такие), тип «Автопродление»:

   | ID базового плана | Период | Пример цены |
   |---|---|---|
   | `monthly` | 1 месяц | $2.99 (≈ 125 ₴) |
   | `quarterly` | 3 месяца | $6.99 (≈ 290 ₴) |
   | `yearly` | 1 год | $19.99 (≈ 830 ₴) |

   Задай цену в базовой валюте (например, в долларах) — Play пересчитает её для каждой страны,
   а цену для Украины можно поправить вручную в гривнах. Пользователь видит цену в валюте своего
   аккаунта Google Play (в Украине — ₴). **Активируй** каждый план. Приложение само посчитает
   «≈ цена в месяц» и скидку для 3 и 12 месяцев.
4. (Необязательно) **Предложение** с бесплатным пробным периодом, например 7 дней на `yearly`
   для новых подписчиков. Приложение покажет «7 дн. бесплатно» и кнопку «Попробовать».

## 6) Проверить покупку

1. **Настройки → Тестирование лицензий** → добавь свой Google-аккаунт. Тестовые покупки
   бесплатны, подписки продлеваются каждые несколько минут (месяц ≈ 5 минут).
2. Поставь сборку из внутреннего тестирования на **реальный телефон** (на эмуляторе Play
   Billing обычно не работает) → Главная → плашка «Striva Премиум» → тариф → оплата.
3. Проверь: появилось «Премиум включён», в профиле «Активен до …», в Supabase —
   строка в `billing_purchases` и `profiles.premium_until`. Через ~5 минут (тестовое продление)
   перезапусти приложение — срок должен сдвинуться.
4. Отмена: Google Play → Платежи и подписки → отменить → в приложении «Автопродление
   выключено», доступ до конца срока.

## 7) Выкатить

Мерж PR (Render задеплоит бэкенд) → в Play Console продвинь сборку 1.1.0 из внутреннего
тестирования в продакшн. Порядок важен: бэкенд раньше приложения.

## Выдать Премиум вручную (подарок, компенсация, тест без оплаты)

Supabase → SQL Editor:

```sql
update public.profiles
   set premium_until = now() + interval '1 month', premium_plan = 'monthly', premium_source = 'manual'
 where id = '<uuid пользователя>';
```

Через Table editor это поле поменять тоже можно (там работает роль postgres). Ручную
выдачу пересчёт подписок не затирает.

## Что важно знать

- **Валюта**: цены приходят из Google Play в валюте аккаунта покупателя (Украина — ₴, США — $
  и т.д.), в коде их нет.
- **Россия**: Google Play не принимает платежи от пользователей из РФ (российские карты не
  работают с 2022 года) — если такие пользователи есть, оплатить Премиум они не смогут.
- **Удаление аккаунта не отменяет подписку Google Play** — приложение предупреждает об этом
  в диалоге удаления, если подписка с автопродлением.
- **Возвраты** делаются в Play Console → Заказы; бэкенд снимет Премиум при следующей
  проверке (не позже чем через 12 часов, когда пользователь откроет приложение).
- **Telegram-бот** (`backend/tgbot.py`) по-прежнему продаёт старые тарифы «Тренер» / «ИИ-чат»
  за Stars, которые пишут `trainer_until` / `ai_plan` — после сентябрьского удаления оплат эти
  поля в приложении ничего не открывают. Кнопку «Тарифы» в боте стоит убрать или перевести на
  выдачу `premium_until` (`premium_source = 'telegram'`).
