# Публикация в Google Play — разовая настройка и обновления

Коротко: **разовая настройка** ниже (создать карточку в Play Console + service account)
делается один раз. После неё **любое** будущее обновление — это одна команда из
`frontend/`, без повторного похода в Play Console руками.

Готовые тексты и картинки для карточки — в `marketing/play-store/`:
- `listing-ru.md` — название/описания для копипаста
- `icon-512.png`, `feature-graphic-1024x500.png` — сгенерированы из настоящего лого
- `data-safety.md` — как заполнить форму Data Safety
- `screenshots/` — скриншоты с реального устройства

## Часть 1 — разовая настройка (нужно один раз)

### 1.1 Создать карточку приложения в Play Console

У тебя уже есть проверенный аккаунт разработчика, самого приложения ещё нет.

1. [play.google.com/console](https://play.google.com/console) → **Создать приложение**.
2. Название: `Striva`, язык по умолчанию — русский, тип — приложение, бесплатное.
3. Заполни разделы **«Настройка приложения»** (все пункты с восклицательным знаком,
   пока не станут зелёными):
   - **Основная карточка магазина** — вставь текст и картинки из `marketing/play-store/`.
   - **Политика конфиденциальности** — вставь ссылку:
     `https://claude.ai/code/artifact/af27e39b-05d2-4b94-b0ea-87bc46f4aae8`
   - **Безопасность данных** — по `marketing/play-store/data-safety.md`.
   - **Возрастной рейтинг** (анкета IARC) — заполни честно: без насилия/контента 18+,
     содержит генерируемый ИИ текст (отметь пункт про ИИ, если анкета его спрашивает).
   - **Реклама** — «Нет», в приложении нет рекламы.
   - **Основное назначение приложения / целевая аудитория** — 18+ или общая аудитория
     без спецпредложений для детей (см. раздел 9 Privacy Policy — приложение не для
     младше 16).
   - **Соответствие требованиям госорганов / вредоносное ПО и т.п.** — стандартные "нет".
4. Package name уже жёстко задан в коде: `com.ttdregon.mysafeapp` — при создании
   приложения в Play Console укажи именно его.

### 1.2 Service account — чтобы `eas submit` заливал сборки автоматически

Без этого шага каждую сборку пришлось бы заливать в Play Console руками через браузер.
С ним — одна команда с компьютера.

1. [console.cloud.google.com](https://console.cloud.google.com) → создай (или выбери)
   проект → **APIs & Services → Library** → включи **Google Play Android Developer API**.
2. **IAM & Admin → Service Accounts → Create service account** (имя любое, например
   `striva-eas-release`). Роль на этом шаге не важна.
3. У созданного service account → **Keys → Add key → Create new key → JSON** — скачается
   файл. Сохрани его как:
   ```
   frontend/secrets/play-service-account.json
   ```
   Эта папка уже в `.gitignore` — файл никогда не попадёт в git, это ожидаемо и правильно.
4. Обратно в **Play Console → Пользователи и права доступа → Пригласить пользователей** —
   пригласи email service account'а (вида `...@...iam.gserviceaccount.com`, он есть в
   самом JSON-файле как поле `client_email`). Права: **Release manager** (или "Admin",
   если Release manager не даёт залить самый первый релиз) на приложение Striva.

После этого `eas.json` уже настроен (`submit.production.android`) и ничего больше
трогать не нужно.

### 1.3 Первый релиз

Первую сборку и заливку тоже делает EAS (см. команды ниже, раздел 2.2) — Play Console
руками для этого открывать не нужно, кроме самого создания карточки (1.1). После заливки
зайди в Play Console → раздел **Production** → увидишь черновик релиза → **Review release
→ Start rollout to Production** (сборка приезжает как черновик — `releaseStatus: draft`
в `eas.json`, специально, чтобы ты сам нажимал публикацию, а не гнала в продакшн
автоматом).

## Часть 2 — как выкладывать любое обновление после этого

Есть два разных пути. Выбирай по тому, **что именно** ты поменял.

### 2.1 Быстрый путь — обновил только код (JS/TS), без новых нативных модулей

Подходит почти для всех правок: экраны, стили, логика, тексты, промпты бэкенда (бэкенд —
отдельно, деплоится сам через Render при пуше в git, см. `CLAUDE.md`/историю коммитов).
Это то, чем мы весь сегодняшний день и занимались.

```bash
cd frontend
eas update --branch production -m "краткое описание изменений"
```

Обновление прилетает пользователям **прямо поверх уже установленного приложения**, без
похода в Play Store и без ревью — при следующем открытии приложения. Не нужно ни бампать
версию, ни собирать новый `.aab`.

**Когда это НЕ подойдёт**: если правка добавляет новый нативный модуль (новый пакет с
нативным кодом в `package.json`), меняет иконку/сплэш/permissions/`app.json` в нативной
части — тогда нужен путь 2.2, иначе у пользователей с уже установленной версией
обновление либо не применится, либо приложение может упасть.

### 2.2 Полный путь — новая сборка в Play Store

Нужен при нативных изменениях (новый пакет с нативным кодом, иконка, permissions,
`android/ios`-специфичные правки) или просто когда хочешь выпустить полноценную новую
версию с ревью Google.

```bash
cd frontend

# (необязательно, но рекомендуется) бампни человекочитаемую версию в app.json:
#   "version": "1.0.0" -> "1.1.0"
# versionCode для Android EAS увеличивает сам (autoIncrement в eas.json), трогать не надо.

eas build --profile production --platform android
# дождись сборки (обычно 10-20 минут, EAS шлёт письмо/уведомление)

eas submit --profile production --platform android
# зальёт готовый .aab в Play Console как черновик релиза
```

Дальше — Play Console → Production → **Review release → Start rollout**. После этого
Google обычно проверяет релиз от нескольких часов до пары дней (у уже одобренного
разработчика — как правило быстрее, чем самый первый релиз).

### 2.3 Что использовать по умолчанию

Если сомневаешься — начни с **2.1 (`eas update`)**. Это буквально то же самое, что
`npx expo run:android` + Metro, которым мы тестировали весь день, только вместо твоего
компьютера JS-бандл раздаёт сервер EAS, а не Metro. Путь 2.2 нужен реже, чем кажется.

## Шпаргалка команд

```bash
# быстрое обновление (99% правок)
cd frontend && eas update --branch production -m "сообщение"

# полная сборка + заливка в Play Store
cd frontend && eas build --profile production --platform android
cd frontend && eas submit --profile production --platform android

# статус последних сборок/обновлений
cd frontend && eas build:list --limit 5
cd frontend && eas update:list --branch production --limit 5
```
